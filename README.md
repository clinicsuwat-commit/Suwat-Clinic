# Suwat Clinic v3.2.0

พอร์ทัลคนไข้และแดชบอร์ดสตาฟภาษาไทย–อังกฤษ โทนน้ำเงินแบบ Bento Grid ใช้ Supabase, Vercel และ LINE OA

## ทางเข้าและขั้นตอนงาน

| ผู้ใช้ | ทางเข้า | งานที่ทำได้ |
|---|---|---|
| คนไข้และผู้ดูแล | `/` หรือเมนู LINE OA | ดูนัดครั้งถัดไป จองคิว แสดงบัตร QR และติดต่อคลินิก กด **ขยายตัวอักษร** จากหน้าหลักได้ |
| สตาฟ | `/staff` | ตรวจคิวตามวันและสาขา ค้นหาชื่อหรือเลขนัด สแกนบัตรและเช็กอิน งานด้านยาขึ้นตามสิทธิ์ |
| ผู้บริหาร | `/manager` | ดูภาพรวมคิวสองสาขาและงานค้าง จัดการสาขา แผนที่ การจอง และสิทธิ์ด้านยา |

คนไข้จองคิวจาก **เลือกคนไข้และสาขา → เลือกวันและช่วงเวลา → ตรวจสอบก่อนส่ง** เพิ่มเบอร์โทรได้ในขั้นแรก และเปิดรายละเอียดนัดจากหน้าผลการส่งได้ทันที ทั้งสามหน้ารองรับภาษาไทยและอังกฤษ

บัญชี Owner ใช้เซสชันเดียวกันขณะสลับระหว่าง `/staff` และ `/manager` บนโดเมนคลินิกเดียวกัน เมื่อเซสชันหมดอายุ ระบบเก็บวัน สาขา และเมนูจากลิงก์เดิมให้กลับมาทำงานต่อหลังเข้าสู่ระบบ

## ติดตั้งและอัปเดต

1. เปิด **Supabase → SQL Editor → New query** แล้วรันไฟล์ SQL ตามเวอร์ชันเดิม

   | โปรเจกต์เดิม | ไฟล์ที่ต้องรันตามลำดับ |
   |---|---|
   | v3.1 ถึง v3.1.3 | ไปที่ขั้นตอนที่ 2 เพื่ออัปเดตโค้ด |
   | v3.0 | `sql/04_branches_medication_stock.sql` |
   | v2.2 | `sql/03_clinic_v3.sql` แล้วตามด้วย `sql/04_branches_medication_stock.sql` |
   | v2.1 | `sql/02_line_phone_no_otp.sql`, `03_clinic_v3.sql`, `04_branches_medication_stock.sql` |
   | โปรเจกต์ใหม่ | `sql/01_setup.sql`, `02_line_phone_no_otp.sql`, `03_clinic_v3.sql`, `04_branches_medication_stock.sql` |

2. แตก ZIP แล้วคัดลอกไฟล์ภายในไปยังรากของ GitHub Repository เดิม ให้ `api/`, `lib/`, `public/`, `sql/`, `package.json` และ `vercel.json` อยู่ระดับเดียวกัน จากนั้น Commit ไปที่ branch สำหรับทดสอบ เมื่อทดสอบเครื่องจริงผ่านทั้งสองระบบแล้วจึงรวมเข้า Production Branch
3. ตรวจ Environment Variables เดิมใน Vercel โดยเฉพาะ `PUBLIC_BASE_URL` และ `CRON_SECRET` แล้วตรวจผลที่ `/api/health` ให้เห็น `"ok": true` และ `"patch": "3.2.0"`
4. เข้าหน้า **`/manager` → ตั้งค่าคิวและสาขา** ด้วยบัญชี Owner แล้ววางลิงก์แชร์พิกัด Google Maps ที่ตรวจแล้วของสาขาอุบลและสาขายโสธร
5. ในหน้า **`/manager` → บัญชีและสิทธิ์** ตรวจสิทธิ์บันทึกและทบทวนยาของสตาฟ แล้วให้ผู้ที่รับผิดชอบเข้าหน้า **`/staff` → สต็อกยา** เพื่อเพิ่มรายการและรับยอดตามล็อตลงสาขา
6. ทดสอบสแกน QR บนมือถือและรับข้อความ LINE OA ด้วยบัญชีทดสอบของคลินิกก่อนใช้งานจริง

สำหรับโปรเจกต์ใหม่ ให้สร้างผู้ใช้ใน **Supabase → Authentication → Users** แล้วเพิ่มบัญชี Owner ด้วย SQL นี้ โดยใช้ชื่อและอีเมลของผู้ใช้ที่สร้างแล้ว

```sql
insert into public.sw_staff(auth_user_id,email,display_name,role)
select id,email,'ชื่อผู้ดูแลคลินิก','owner'
from auth.users where email='owner@example.com'
on conflict(auth_user_id) do nothing;
```

ตั้ง Framework Preset เป็น **Other** และใช้โฟลเดอร์รากของโค้ดเป็น Root Directory ไฟล์ `vercel.json` กำหนด Output Directory เป็น `public`

## ตั้งค่า LINE และตัวเตือน

| ตัวแปร | ค่า |
|---|---|
| `SUPABASE_URL` | Project URL ของ Supabase |
| `SUPABASE_PUBLISHABLE_KEY` | Publishable Key สำหรับตรวจบัญชีสตาฟใน Supabase Auth |
| `SUPABASE_SECRET_KEY` | Secret Key ฝั่งเซิร์ฟเวอร์ |
| `LINE_LOGIN_CHANNEL_ID`, `LINE_LIFF_ID` | LINE Login Channel ID และ LIFF ID ของระบบ เลือก Scope `openid` ใน LIFF และตั้ง Endpoint URL ไปที่โดเมนรากของคลินิก |
| `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET` | ช่องทาง Messaging API ของ LINE OA ควรอยู่ใต้ Provider เดียวกับ LINE Login |
| `LINE_OA_URL` | ลิงก์เพิ่มเพื่อน/เปิดแชต LINE OA สำหรับปุ่มติดต่อคลินิก |
| `PUBLIC_BASE_URL` | โดเมน HTTPS หลักของคลินิก สำหรับลิงก์แผนที่สาขาและแดชบอร์ดจาก LINE |
| `LINE_STAFF_GROUP_ID` | ไม่ต้องใส่ถ้าเลือกกลุ่มจากหน้า Owner อยู่แล้ว ถ้ากำหนดค่านี้ ระบบใช้กลุ่มจากตัวแปรนี้ก่อน |
| `CRON_SECRET` | สตริงสุ่มยาวสำหรับ Vercel Cron ตั้งใน Production แล้ว Redeploy |

คง Webhook ของระบบนี้ที่ `https://โดเมนคลินิก/api/line/webhook` และกด **Verify** ใน LINE Developers Console ให้คนไข้และสตาฟเพิ่มเพื่อน LINE OA เพื่อรับข้อความแบบ Push สตาฟผูก LINE ส่วนตัวได้หลังเข้าสู่ระบบสตาฟแล้ว

ถ้าเข้า LINE หลังออกจากระบบแล้วขึ้นแจ้งเตือน ให้ปิดหน้า LIFF และเปิดใหม่จากเมนูคลินิกใน LINE ถ้าระบบแจ้งว่าการตั้งค่าไม่ตรงกัน ให้เปิด **LINE Developers → LINE Login → Basic settings** แล้วเทียบ Channel ID กับ `LINE_LOGIN_CHANNEL_ID` ใน Vercel Production ตรวจ `LINE_LIFF_ID` และ Scope `openid` ที่แท็บ **LIFF** ของ Channel เดียวกัน ถ้าปรับค่าใน Vercel ให้ Deploy ใหม่

การ์ด **ขอนัดหมายตรวจล่วงหน้า** ใช้หัว **คลินิกกระดูกและข้อ หมอสุวัฒน์** และแสดงสาขา วัน เวลา สถานะ และเลขนัด ใน LINE ส่วนตัวของคนไข้และสตาฟผู้รับนัดจะแสดงชื่อ เบอร์โทร และประเภทผู้ป่วย คนไข้เห็นเลขที่คนไข้ (HN) เฉพาะ 4 ตัวท้าย สตาฟผู้รับนัดเห็น HN เต็ม หากมีประวัติเช็กอิน ตรวจเสร็จ หรือ HN ที่ผูกแล้ว ระบบจะแสดง **คนไข้เดิม** หากข้อมูลยังไม่ครบจะแสดงสถานะตามจริง กลุ่มสตาฟเห็นสาขา วัน เวลา สถานะ และเลขนัด พร้อมปุ่มเปิดแดชบอร์ด

### ตรวจ LINE บน Android และ iPhone ก่อนเปิดใช้กับคนไข้

ใช้บัญชีทดสอบของคลินิก เช็ก `/api/health` ของเว็บที่ทดสอบให้แสดง `"patch": "3.2.0"` แล้วทำขั้นตอนเดียวกันบนเครื่องจริงทั้งสองเครื่อง

สำหรับ Vercel Preview ให้สร้าง LIFF สำหรับทดสอบใน LINE Login Channel ของคลินิก ตั้ง **Endpoint URL** เป็นโดเมน Preview และตั้ง `LINE_LIFF_ID` ของ Environment **Preview** ให้ตรงกับ LIFF ที่ใช้ทดสอบ

1. เปิด Rich Menu **บัญชีของฉัน** จากแชต LINE รอให้เห็นชื่อสมาชิก แล้วเปิด **การนัดหมาย**
2. กลับมาที่บัญชี กด **ออกจากระบบ** แล้วแตะ **เข้าสู่ระบบด้วย LINE** ชื่อสมาชิกเดิมควรแสดงอีกครั้ง
3. เปิดหน้าเว็บจาก Safari บน iPhone หรือ Chrome บน Android แล้วกด **เปิดในแอป LINE** ถ้าทดสอบทาง **เข้าสู่ระบบบนเว็บ** ให้กดดำเนินการต่อบนหน้า LINE แล้วตรวจว่าหน้าบัญชีแสดงชื่อสมาชิกและยังแสดงอยู่หลังรีเฟรช
4. เปิดข้อความนัดทดสอบใน LINE แตะปุ่มดูรายละเอียด และตรวจว่ากลับมาที่นัดของบัญชีทดสอบ

`vercel.json` เริ่มด้วย `0 0 * * *` เพื่อเรียกตัวเตือนหนึ่งครั้งต่อวันในช่วงเช้าไทย ตรงกับ 07:00 ICT ตามตารางเวลา รอบจะทำงานกับนัดที่ยืนยันแล้วในวันนี้และวันพรุ่งนี้ และชุดยาที่ถึงกำหนดเตือน เวลาเรียกจริงขึ้นกับแพลน Vercel หากใช้แพลนที่รองรับรอบถี่ สามารถเปลี่ยนเป็น `*/10 * * * *` เพื่อให้ระบบเดินคิวสำรองและส่งซ้ำเมื่อเกิดปัญหาได้ถี่ขึ้น ตัวเตือนเช้าจะเริ่มส่งตั้งแต่ 07:00 ตามเวลาไทย และส่งวันละหนึ่งข้อความต่อการเตือนแต่ละแบบ ดูผลที่ **Vercel → Cron Jobs** และในการ์ดแดชบอร์ดสตาฟ [Vercel Cron Jobs](https://vercel.com/docs/schedules/cron-jobs/usage-and-pricing)

Vercel กำหนด Hobby สำหรับงานส่วนตัวที่ไม่ใช่เชิงพาณิชย์ ให้เลือกแพลนที่ครอบคลุมการใช้งานจริงของคลินิก [Vercel Hobby Plan](https://vercel.com/docs/plans/hobby)

## ใช้งานหน้าคลินิก

| เมื่อสแกน | ระบบแสดงให้ทำต่อ |
|---|---|
| บัตรยังไม่มี HN | เทียบชื่อกับทะเบียนของคลินิก กรอก HN เดิม แล้วกดยืนยัน บันทึกเลขศูนย์นำหน้าได้ และ HN เดียวผูกได้หนึ่งโปรไฟล์ |
| ไม่มีนัดวันนี้ | ลงนัดใหม่ เลือกวัน ช่วงเวลา และเวลาที่แน่นอน |
| นัดวันนี้รอยืนยัน | ตรวจรายการและยืนยันนัด |
| นัดวันนี้ยืนยันแล้ว | เทียบผู้มารับบริการกับชื่อและ HN จากนั้นกดเช็กอิน |
| เช็กอินแล้วหรือพบแพทย์เสร็จ | ผู้มีสิทธิ์ด้านยาสแกนบัตรเพื่อบันทึกจำนวนจริงตามใบสั่งยาและเลขอ้างอิง |

คนไข้ที่ผูก LINE แล้วมีบัตรแยกสำหรับตัวเองและคนที่ดูแล QR ใช้ได้ 10 นาที สตาฟใช้กล้อง เลือกรูป QR หรือกรอกรหัสสำรองได้ สำหรับนัดจาก v2.2 ระบบจับคู่นัดจากบัญชี LINE และชื่อคนไข้ในนัดก่อนให้ยืนยัน HN กับทะเบียนคลินิก

รายการซ้ำพิจารณาจาก **คนไข้คนเดียวกันและวันเดียวกัน** ในสถานะรอยืนยัน ยืนยัน หรือเช็กอิน คนในครอบครัวแต่ละโปรไฟล์ตรวจแยกกัน คำขอเลื่อนนัดจะรอผลจากสตาฟและคงนัดเดิมจนอนุมัติ ด้านคิวสำรอง เมื่อมีที่ว่าง ระบบเสนอให้ผู้ที่เข้าคิวก่อนกดรับได้ภายใน 2 ชั่วโมงหรือก่อนช่วงคิวเริ่ม แล้วตรวจความจุอีกครั้งตอนกดรับ

## จองคิวตามสาขา

คนไข้เลือก **สาขาอุบล** หรือ **สาขายโสธร** ก่อนเลือกช่วงเวลา ระบบแยกจำนวนคิวและคิวสำรองตามสาขา และตรวจป้องกันนัดซ้ำของคนไข้คนเดิมในวันเดียวกันทุกสาขา เริ่มจากตารางเปิดบริการและจำนวนคิวมาตรฐานของโปรเจกต์ เจ้าของกำหนดจำนวนคิวและการปิดเฉพาะวันแยกสาขาได้ใน `/manager`

หลังจองและในข้อความเตือนนัด LINE แสดงสาขาพร้อมปุ่มแผนที่ ปุ่มเปิดพิกัดที่บันทึกล่าสุดใน Manager ก่อนตั้งพิกัดจริง ปุ่มจะเปิดผลค้นหาชื่อสาขาใน Google Maps สตาฟกำหนดสาขาให้นัดเดิมที่มีสถานะรอยืนยัน ยืนยัน หรือเช็กอินได้จากแดชบอร์ด โดยเปิดตัวกรอง **ทุกสาขา** เพื่อเห็นนัดที่ยังไม่ได้ระบุ

## สต็อกยาและแจ้งเตือนใกล้หมด

1. สตาฟที่ได้รับสิทธิ์เพิ่มรายการยาในแท็บ **สต็อกยา** แล้วรับเข้าเป็นรายสาขาและล็อต ระบุจำนวนเม็ดและวันหมดอายุของล็อต
2. หลังพบแพทย์ สแกนบัตร QR → **บันทึกการจ่ายยา** เลือกยาจากสต็อกสาขา กรอกจำนวนเม็ด วันที่เริ่มใช้ และวิธีใช้ตามใบสั่งยา พรีเซ็ต **1 เม็ดหลังอาหาร 1, 2 หรือ 3 เวลา** เติมช่องบันทึกให้ตรวจและแก้ได้
3. ระบบนับจากวันเริ่มใช้เป็นวันแรก ตามจำนวนเม็ดและจำนวนครั้งต่อวันจากใบสั่ง แสดงวันที่คาดว่ายาจะใกล้หมด หากเม็ดยาเหลือบางส่วนในวันท้าย ระบบรวมวันนั้นไว้ในประมาณการ ถ้ามีหลายรายการ ระบบยึดวันที่ใกล้หมดเร็วที่สุด วิธีใช้เมื่อจำเป็นหรือปรับขนาดยาใช้ช่องบันทึกของสตาฟโดยไม่มีการคำนวณวันใกล้หมดจากรายการนั้น
4. การบันทึกตัดยอดจากล็อตที่ยังใช้ได้และหมดอายุก่อนในสาขานั้น การส่งแบบฟอร์มซ้ำใช้รายการบันทึกเดิม ระบบไม่ตัดยอดซ้ำ
5. ค่าเริ่มต้นส่ง LINE หนึ่งครั้งต่อชุด ล่วงหน้า **2 วัน** ตามเวลาประมาณการ ผ่าน Cron เดิมของคลินิก ถ้าเวลาที่คำนวณได้อยู่ในช่วงสั้นกว่า 2 วัน ระบบจัดเข้ารอบที่เริ่มได้หลังบันทึก

## คำขอชุดเดิมจาก LINE

- สตาฟเลือกเปิดให้ส่งคำขอชุดเดิมตามที่คลินิกอนุญาตและกำหนดวันสิ้นสุด หากเว้นวันเริ่ม ระบบใช้วันเริ่มเตือนตามประมาณการ
- คนไข้กด **ขอชุดเดิม** จาก LINE หรือหน้า **ประวัติการจ่ายยา** แล้วเข้าสู่แบบฟอร์มด้วยบัญชีสมาชิก LINE เดิม ระบบเติมชื่อและเบอร์ติดต่อจากข้อมูลสมาชิกหรือผู้รับเดิม และใช้ที่อยู่ครั้งล่าสุดถ้ามี คนไข้แก้ไขก่อนส่งได้
- หน้าเว็บคนไข้และการ์ด LINE แสดงสถานะชุดยาและประมาณการแบบไม่ระบุชื่อยา ข้อมูลรายรายการเปิดได้จากระบบสตาฟที่มีสิทธิ์
- ระบบอ้างอิงรายการและปริมาณของชุดเดิม ค่าส่งเหมา **150 บาท** คำขอเข้าคิวให้คลินิกทบทวนก่อนดำเนินการด้านยาและติดต่อคนไข้ [ข้อมูลการให้บริการเภสัชกรรมทางไกลจาก อย.](https://www.fda.moph.go.th/news/telepharmacy/)
